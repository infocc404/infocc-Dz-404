# info cc 404 — منصة طلبة الإعلام الآلي (Ingénieur d'État en Informatique)

موقع ويب تفاعلي ثابت (Static Web App) مبني بـ Vanilla HTML / CSS / JavaScript ومربوط بقاعدة بيانات Supabase، مهيأ للنشر المباشر على GitHub Pages تحت المسار `/info_cc_404/` (الرابط: https://infocc404.github.io/info_cc_404/).

## نموذج الصلاحيات والأمان (Security & Roles Model)

يعتمد التطبيق نظام أمان صارم يفرض على مستوى قاعدة البيانات (PostgreSQL RLS) ومساحة التخزين (Supabase Storage RLS)، دون الاعتماد على واجهة المستخدم كخط دفاع وحيد:

1. **المالك (Owner):**
   - صاحب الصلاحية الكاملة على المنصة.
   - المالك المحدد هو البريد الإلكتروني `locoviber16@gmail.com`.
   - يملك حق تعيين وإلغاء المشرفين (`admins`) ورؤساء الأقسام (`uploaders`).
   - يملك صلاحية رفع وحذف الملفات لجميع الأفواج، إضافة لدروس المحاضرات العامة (`cours`).
   - محمي برمجياً في قاعدة البيانات من أي حذف أو تعديل للرتبة.

2. **المشرف (Admin):**
   - صلاحيات إشرافية محددة تختلف عن المالك.
   - يستطيع رفع وإدارة ملفات جميع الأفواج والمحاضرات العامة.
   - يستطيع تعيين وإلغاء رؤساء الأقسام (`uploaders`) من صفحة الإدارة.
   - **لا يملك** صلاحية تعيين أو إلغاء مشرفين عامين آخرين؛ هذه الصلاحية للمالك وحده.
   - **لا يملك** صلاحية المساس بحساب أو رتبة المالك.

3. **رئيس القسم / رافع الملفات (Uploader / Chef de section):**
   - مفوض لفوج دراسي محدد فقط (بين 1 و 10).
   - لا يمكنه رفع أو حذف أي ملف خارج فوجه الدراسي.
   - لا يمكنه رفع ملفات المحاضرات (`cours`) المخصصة للمشرفين والمالك.
   - مسار التخزين محصور داخل مجلد فوجه حصراً: `course-files/g{group_no}/...`.
   - لا يستطيع تعديل صلاحياته أو رتب أي مستخدم آخر.

4. **الطالب (Student):**
   - يتم تحديد وتوثيق فوجه الدراسي حصريا من جدول `public.student_profiles` (المصدر الموثق Authoritative Source).
   - لا يُعتمد مطلقا على بيانات `raw_user_meta_data`، ولا يمكن لأي طالب تغيير فوجه عبر تعديل بيانات حسابه.
   - يطّلع فقط على المحاضرات العامة (`cours`) والملفات العامة (`group_no is null`) وملفات فوجه الدراسي المسجل فيه.
   - تفرض سياسات RLS عدم ظهور ملفات الأفواج الأخرى في أي استعلام أو استدعاء للـ API.
   - تمنع سياسات Storage إنشاء أي رابط موقّع (Signed URL) لأي ملف لا ينتمي لفوجه.
   - لا يملك أي صلاحية رفع أو تعديل أو حذف.

## تطبيق الترحيل الأمني على Supabase (Applying Migration v9)

1. افتح مشروعك في **Supabase Dashboard**.
2. توجّه إلى **SQL Editor** ثم اضغط على **New query**.
3. الصق محتوى الملف `migration_security_v9.sql` واضغط **Run**.
4. تأكد من ظهور رسالة النجاح داخل المعاملة (Success).

## هيكلة مسارات التخزين السحابي (Storage Hierarchy)

يتم تخزين الملفات داخل الحافظة الخاصة `course-files` وفق هيكلية مجلدات واضحة تفرض سياسات RLS عليها:
- `common/{timestamp}_{hash}.pdf`: الملفات المشتركة ودروس المحاضرات (رفع: المالك والمشرف فقط | قراءة: الجميع).
- `g{N}/{timestamp}_{hash}.pdf`: ملفات الفوج N من أعمال موجهة وتطبيقية وامتحانات (رفع وحذف: المالك، المشرف، ورئيس الفوج N فقط | قراءة: المالك، المشرف، وطلبة الفوج N فقط).

## الأساتذة والجدول الزمني (Teachers & Timetable)

- **لا توجد بيانات أساتذة أو حصص داخل الكود.** كل شيء يُدخل من التطبيق ويُحفظ في Supabase.
- **الأساتذة** (جدول `teacher_info`): يضيف المالك والمشرف الأساتذة من صفحة الأساتذة عبر زر «إضافة أستاذ». أساتذة المحاضرة (`cours`) يُخزَّنون بـ `group_no = NULL`، وأساتذة TD/TP بفوج من 1 إلى 10.
- **البرنامج الدراسي**: يستخدم واجهة PDF سجل `public.files` مع مسار `common/` للبرنامج المشترك أو `gN/` لبرنامج فوج محدد. لم تعد الواجهة تعتمد على إدخال الحصص يدويًا أو أعمدة `schedule_entries.start_time` و`day_of_week`.
- **المشرفون**: يعيّنهم المالك فقط من صفحة "الإدارة". رؤساء الأقسام يعيّنهم المالك أو المشرف ويرفعون ملفات فوجهم فقط.

### أول تشغيل بعد التحديث
1. شغّل `migration_schedule.sql` في **SQL Editor**.
2. لمسح البيانات التجريبية: شغّل `reset_demo_data.sql`، ثم امسح ملفات PDF من **Storage → course-files**.

## ملاحظة عن رابط استرجاع كلمة المرور
عند فتح الرابط من البريد يبقى التطبيق على صفحة "كلمة سر جديدة" (`recoveryMode`) حتى تُحفظ الكلمة الجديدة، ثم يفتح التطبيق مباشرة.
